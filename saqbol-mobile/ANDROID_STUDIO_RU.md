# SaqBol Mobile — запуск в Android Studio (macOS)

Backend уже развёрнут на сервере: **http://89.167.96.246:8082**
Приложение запускается на твоём Mac и ходит на этот адрес.

---

## Шаг 0. Что должно быть установлено

| Что | Как проверить / поставить |
|---|---|
| Android Studio | https://developer.android.com/studio |
| Flutter SDK 3.41+ | `brew install --cask flutter`, затем `flutter --version` |
| Плагины Flutter + Dart | Android Studio → Settings → Plugins → искать «Flutter», поставить (Dart подтянется сам) → Restart IDE |

После установки обязательно:

```bash
flutter doctor
```

Все пункты Android должны быть зелёными. Если ругается на лицензии:

```bash
flutter doctor --android-licenses    # и принять все
```

---

## Шаг 1. Забрать код

```bash
cd ~/Desktop
git clone https://github.com/DanialMyrzatayevMuratovich/saqbol.git
cd saqbol/saqbol-mobile
flutter pub get
```

---

## Шаг 2. Открыть проект

Android Studio → **Open** → выбрать папку **`saqbol/saqbol-mobile`**

Важно: открывать именно `saqbol-mobile`, а не корень `saqbol`. Если открыть
корень, IDE не увидит Flutter-проект и кнопка Run будет неактивна.

Дождись, пока внизу закончится Gradle sync (первый раз — несколько минут,
скачиваются зависимости).

---

## Шаг 3. Создать эмулятор

Android Studio → **Tools → Device Manager** → **Create Device**

- Устройство: Pixel 6 (или любое)
- Образ системы: API 34 (Android 14), при необходимости нажать Download
- Finish → нажать ▶ рядом с созданным устройством, дождаться загрузки Android

Вместо эмулятора можно подключить реальный телефон по USB с включённой
отладкой по USB — он появится в списке устройств сам.

---

## Шаг 4. ГЛАВНОЕ — прописать адрес сервера

Без этого приложение не заработает: в коде зашит дефолт
`http://localhost:8080`, а на телефоне «localhost» — это сам телефон,
а не твой сервер. Адрес передаётся флагом при запуске.

**Run → Edit Configurations…** → выбрать конфигурацию `main.dart` →
поле **Additional run args** вставить:

```
--dart-define=API_BASE_URL=http://89.167.96.246:8082
```

→ Apply → OK

Это делается один раз, настройка сохраняется в проекте.

---

## Шаг 5. Запуск

Вверху выбрать эмулятор в списке устройств → нажать ▶ **Run** (или `Ctrl+R`).

Первая сборка — 2–5 минут. Дальше используй **Hot Reload** (⚡ или `Cmd+\`)
— изменения применяются за секунду без перезапуска.

## Шаг 6. Войти

| Поле | Значение |
|---|---|
| Телефон | `+77075201006` |
| Пароль | `danial0001` |

Номер вводить строго с `+7` — backend сравнивает строку посимвольно,
вариант `7075201006` вернёт ошибку входа.

Проверить работу: экран проверки SMS → вставить текст
`Служба безопасности банка, назовите код из смс` → должен появиться
красный вердикт «мошенничество» с подсвеченными триггерными фразами.

## Если не работает

**Приложение не логинится / бесконечная загрузка**

Проверь с Mac, что сервер виден:

```bash
curl http://89.167.96.246:8082/health     # ожидается {"status":"ok"}
```

Если curl отвечает, а приложение нет — почти наверняка забыт флаг
`--dart-define` из шага 4. Проверь Edit Configurations.

**Кнопка Run неактивна / нет устройств**
Открыта не та папка (нужна `saqbol-mobile`) либо не запущен эмулятор.

**Gradle sync failed**
File → Invalidate Caches → Invalidate and Restart. Затем в терминале:

```bash
cd ~/Desktop/saqbol/saqbol-mobile
flutter clean && flutter pub get
```

**Ошибки сети только на iOS**
На iOS обычный HTTP заблокирован системной политикой ATS, исключения
в проекте нет. Используй Android — там cleartext HTTP уже разрешён.

## Без Android Studio, из терминала

То же самое одной командой:

```bash
cd ~/Desktop/saqbol/saqbol-mobile
flutter run --dart-define=API_BASE_URL=http://89.167.96.246:8082
```

Собрать APK, чтобы поставить на реальный телефон:

```bash
flutter build apk --dart-define=API_BASE_URL=http://89.167.96.246:8082
# готовый файл: build/app/outputs/flutter-apk/app-release.apk
```

Адрес сервера вшивается в APK при сборке — под другой сервер нужна пересборка.

## Важно

Этот файл содержит пароль от админского аккаунта — **не коммить его
в репозиторий**, он публичный. Держи только локально.

Сервер сейчас работает по HTTP без шифрования и без firewall, то есть
пароли передаются открытым текстом. Для демонстрации это приемлемо,
для реальных данных нужен домен с TLS.
