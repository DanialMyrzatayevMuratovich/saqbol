## Расхождения с CLAUDE.md

### 1. `docker compose` не существует — только `docker-compose`
Плагина CLI нет (`/usr/libexec/docker/cli-plugins` содержит лишь `docker-trust`),
есть бинарь `/usr/local/bin/docker-compose` v2.26.1. Ранбук допускает оба
варианта — здесь работает только второй.

### 2. Порты 3000 / 8080 / 8000 заняты продакшном
На хосте ~30 чужих контейнеров (`argus-*`, `webizon-*`, `task-service-*`,
`eduser-*`): 3000 — `argus-frontend-app`, 8080 — `argus-backend-app`,
8000 — `webizon-centrifugo`, 9090 — `webizon-prometheus`.

Задано в `.env` (git-ignored, `chmod 600`): web **3010**, backend **8082**,
ml **8002**. Раньше это делал `docker-compose.override.yml` — он **отключён**
(лежит как `docker-compose.override.yml.bak`), потому что после `91724a4`
порты параметризуются штатно. Не возвращай его: два механизма конфликтуют.

**Без `.env` compose возьмёт дефолты 3000/8080/8000 и столкнётся с продом.**
Файл обязателен до первого `up`.

### 3. Баг репозитория: сборка ML падает при чистом клоне
`saqbol-ml/app/generated/` в `.gitignore`, `protoc` не создаёт выходную
директорию → `No such file or directory`, сборка встаёт. **Исправлено**
в `saqbol-ml/Dockerfile` (коммит `f02a053`, влит в `main`):

```dockerfile
RUN mkdir -p app/generated \
    && python -m grpc_tools.protoc \
```

Не откатывай эту строку — сборка ML сломается у всех, кто клонирует репозиторий.

## Конфигурация

`.env` (не в git):
```
POSTGRES_PASSWORD=saqbol          # см. ниже — менять нельзя без ALTER USER
JWT_ACCESS_SECRET / JWT_REFRESH_SECRET   # случайные, openssl rand -hex 32
ADMIN_PHONES=+77075201006
BACKEND_PORT=8082  WEB_PORT=3010  ML_PORT=8002
BACKEND_BIND=0.0.0.0  WEB_BIND=0.0.0.0  ML_BIND=127.0.0.1
WEB_API_BASE_URL=http://89.167.96.246:8082
```

**`POSTGRES_PASSWORD` нельзя просто поменять.** Том `pgdata` уже
проинициализирован с паролем `saqbol`; Postgres задаёт пароль только при
первом старте на пустом каталоге. Новое значение в `.env` уйдёт в
`DATABASE_URL` бэкенда и тот потеряет доступ к БД, при этом healthcheck
postgres останется зелёным (`pg_isready` пароль не проверяет). Выглядит как
«база жива, приложение сломалось», и напрашивается `down -v` — то есть
уничтожение данных. Правильный порядок: сначала
`ALTER USER saqbol PASSWORD '<новый>'` в живой БД, потом то же значение в `.env`.

## Текущее состояние

Пять контейнеров подняты. ML слушает только `127.0.0.1:8002` (снаружи
недоступен, проверено). Сквозной тест пройден: `verdict: "scam"`,
`model_version: "baseline-tfidf-logreg-v1"`. Все три админ-эндпоинта дают 200,
обычному пользователю — 403.

- Web: http://89.167.96.246:3010
- API: http://89.167.96.246:8082

Пользователи (телефоны приведены к единому формату E.164; нормализации
в коде **нет**, backend сравнивает строку посимвольно — новые регистрации
могут снова создать записи в другом формате):

| Телефон | Пароль | Роль |
|---|---|---|
| `+77075201006` | `danial0001` | admin |
| `+77000000001` | `secret123` | user |

Роль `admin` выдаётся только через `ADMIN_PHONES` при старте backend
(`UPDATE users SET role='admin' WHERE phone = ANY(...)`). Пользователь должен
существовать заранее — незарегистрированный номер молча не повысится.
Понижения в коде нет: убрать номер из `.env` роль не отнимет, только SQL.
Ролей всего две, `superadmin` не существует.

## Сделано после первого развёртывания

- **Автозащита SMS** — `POST /sms/check/batch` (до 100 сообщений за запрос),
  вкладка «Защита» в приложении: сканирование входящих, проверка новых
  сообщений в фоне, уведомления при вердикте `scam`.
- **Скрининг звонков** — `CallGuardService` (Kotlin) сверяет номер входящего
  с `GET /numbers/:number/risk`. Звонок всегда пропускается, показывается
  предупреждение. Аудио разговора недоступно: Android запрещает это с API 29.
- **Тёмная тема** для веба и приложения на общих токенах. Цвета вердиктов
  подобраны по валидатору (диапазон яркости, контраст ≥3:1); различимость
  красного и янтарного при дальтонизме ΔE 6.1 — пограничная, поэтому цвет
  нигде не единственный носитель смысла (иконки, подписи, зазоры).

Всё влито в `main` и запушено.

  `flutter analyze`, `flutter test` и сборка APK — проходят.
- **Скрининг звонков не проверен на живом устройстве** — только компиляция.
- **Вёрстка не просмотрена глазами** — токены доехали до продакшн-CSS,
  но переносы и поведение на узких экранах не проверялись.
- **Flutter на сервере не установлен** (хост headless); сборки и анализ
  гонялись в контейнере `ghcr.io/cirruslabs/flutter:stable`.
- **Модель даёт ложные срабатывания** — «Привет, встречаемся в 5» получает
  `suspicious` 0.46. При автопроверке всех SMS это станет заметно; порог
  `SUSPICIOUS_THRESHOLD=0.45` стоит поднять или дообучить модель.

## Осталось по безопасности

JWT-секреты теперь случайные — главная дыра закрыта. Но:
- **firewall выключен** (`ufw inactive`, `iptables INPUT policy ACCEPT`),
  API и веб открыты в интернет;
- **HTTP без TLS** — пароли идут открытым текстом;
- пароль БД остался `saqbol` (Postgres порт наружу не публикует, риск
  ограничен доступом к самому хосту).

Для приватного доступа: `BACKEND_BIND=127.0.0.1` в `.env` + SSH-туннель
`ssh -L 8082:127.0.0.1:8082 root@89.167.96.246` (тогда веб надо пересобрать
с `WEB_API_BASE_URL=http://localhost:8082`).

## Эксплуатационные заметки

- Диск: было 86% занято / 22G свободно, образы добавили ~1G. Проверяй
  `df -h /root` перед сборками.
- `docker-compose down -v` сотрёт том с БД. Не использовать.
- У `web` адрес API вшивается **на этапе сборки** (`build.args`), а не
  в рантайме — смена `WEB_API_BASE_URL` требует `up -d --build web`.
  `localhost` в этом значении означает машину браузера, а не сервер.
- Продакшн-контейнеры за всю сессию не затрагивались — сохраняй это свойство.
- Не пиши `docker-compose ... | tail -N` при сборке без `set -o pipefail`:
  exit code уедет на `tail`, упавшая сборка отрапортует успехом.
